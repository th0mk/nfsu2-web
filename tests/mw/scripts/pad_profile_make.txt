# Most Wanted: the first of two runs that load profiles saved with a controller's bindings (TRACKER M6-37; PLAN D-65;
# the save tree this run leaves seeds pad_profile_load.txt).  With the pad plugged in from the first frame, a first
# start makes PADA and PADB as profiles_make.txt makes ALPHA and BRAVO.  Before each is saved, the joystick bindings
# runtime/mw/pad_mw.c changed are poked back to the game's own layout for a pad it does not know by name (the
# pad_binds run of a build before pad_mw.c; GAME.md 13.1): X gas, B brake, A handbrake, Y Speedbreaker, LT nitrous,
# RB respawn, LB look back, RT pause, no gears, no camera.  PADA is saved so, as a build before pad_mw.c saved a
# profile; PADB with the player's own gas on Y as well.  The table 0x91F418 holds 76 rows of 0x34 bytes, the first
# joystick binding (type, device, code) at +0x1C; a poke writes the type and the code of rows 0, 1, 4..9, 15, 16, 18
# (types 2 a button, 0 none; button codes 0 X, 1 A, 2 B, 3 Y, 4 LB, 5 RB, 6 LT, 7 RT).  The save keeps rows 0..18
# and the pad's name hash.
#   NFSU2_SAVE_SEED=<a folder holding only d3dx9_26.dll> node web/tools/run-suite.mjs --game mw \
#     --script pad_profile_make.txt --marker 'pad_profile_make: PADB saved' --env NFSMW_D3DX=/save/d3dx9_26.dll \
#     --env FILELIST=1 --env NFSU2_PAD_LOG=1 --env NFSU2_QUIT_FRAMES=9000 --save-out DIR
