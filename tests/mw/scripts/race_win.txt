# Most Wanted: a quick race won over the finish line by the game's AI driving the player's car, and saved (TRACKER
# M4-02, L-022).  Seeded with the save tree profiles_make.txt leaves (ALPHA and BRAVO; NFSU2_SAVE_SEED), this run
# loads ALPHA from the start's Load list (as profiles_load.txt does) and sets up a Custom Race the AI-driven car can
# win: Quick Race, Custom Race (the "quick race" menu's 2nd item), Sprint ("custom race mode select": Circuit,
# Sprint, Drag, Lap Knockout, Speedtrap), the first track, Seaside & Power Station (3.8 miles), and in "sprint
# options" (rows Traffic Level, Opponents, Difficulty, Catch Up; LEFT steps a value back) no traffic, 1 opponent,
# Easy and no catch-up; the car the car list starts on, automatic gears ("Select your transmission": Auto).  From GO the
# game's AI drives the player's car (autopilot) until the player's racer is finished (GRaceStatus [0x91E000] slot
# #0's byte +0x21 at +0x39): the race's own script runs the whole finish (checkpoints, laps, ranking, placement),
# not the racewin shortcut (runtime/mw/career_mw.c), so the race and lap times are driven ones.  After the winner's
# post-race screen (InGamePhotoMaster.fng) it goes back to the main menu and saves ALPHA from the Alias Manager (as
# profiles_load.txt does), so the save tree it leaves (--save-out) next to the seed's shows what the game itself
# wrote for the win (L-022: nothing here edits a reward or the career).  The AI can lose: the winner's screen then
# never comes (TIMEOUT), and the racestatus before it says where the player came.
# tests/mw/checks/race_win.sh wants the load, the win and the save, in that order:
#   NFSU2_SAVE_SEED=DIR/profiles_make node web/tools/run-suite.mjs --game mw --script race_win.txt \
#     --marker 'race_win: ALPHA saved' --env FILELIST=1 --env NFSU2_QUIT_FRAMES=60000 --timeout-scale 3 \
#     --save-out DIR2
# (an oracle build also needs the D3DX seed of tests/mw/scripts/boot_menu.txt; profiles_make's tree holds it)
# (*) The load is quick: "Load complete." is up, taking input with Continue highlighted, 3 frames after the boot
# list's RETURN.  A RETURN tapped at once is dropped (one 8 or 30 frames on is taken; the dialog shows no change in
# between, so the cause is taken to be that first tap still holding the key, 6 frames: no new press).  So Continue
# is pressed until the main menu comes: a press that falls in the hold is followed by one 90 frames on.
