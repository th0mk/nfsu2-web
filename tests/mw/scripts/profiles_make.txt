# Most Wanted: the first of three runs that make, load and delete aliases across restarts (TRACKER M3-20; the save
# tree each run leaves seeds the next: profiles_load.txt, then profiles_gone.txt).  This one, from a first start,
# makes ALPHA and saves it (as kb_alias.txt makes ROTEST), then makes BRAVO with the Alias Manager's Create and saves
# that too.  Every step acts on its screen or dialog (L-021): the dialogs inside MC_Main.fng by what it shows and
# highlights (kb_alias.txt says how; runtime/mw/fe_mw.c mw_fe_match).  The steps after the first alias:
#   the main menu's Alias Manager (its 7th item, 0x4B4E3890) opens MC_ProfileManager.fng: Create, Load, Save, Delete,
#   left to right (no wrap; 0x4B4E388A on); Create asks "Creating a new alias will result in any unsaved changes to
#   the current alias being lost. Are you sure you want to create a new alias?" (label 0x7209349F, No highlighted):
#   Left, Enter; the two autosave notes: Enter, Enter; "Enter name: NAME": Backspace x4, BRAVO, Enter (Accept);
#   "Do you want to save the alias BRAVO?" (No highlighted): Left, Enter; "Save complete.": Enter, back to the Alias
#   Manager with BRAVO the current alias.
# tests/mw/checks/profiles_make.sh wants both saves written, in that order:
#   node web/tools/run-suite.mjs --game mw --script profiles_make.txt --marker 'profiles_make: BRAVO saved' \
#     --env FILELIST=1 --env NFSU2_QUIT_FRAMES=9000 --save-out DIR
# (an oracle build also needs the D3DX seed of tests/mw/scripts/boot_menu.txt; DIR/profiles_make/ then holds the DLL
# too, so it seeds the next run as it is)

+0    tap RETURN

+0    tap RETURN
+0    waitfng MC_Main.fng:b380362f 600
+0    tap RETURN
