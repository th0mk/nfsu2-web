# Most Wanted: the main menu picks Options by the mouse alone (TRACKER M3-08, M3-32), the same walk twice: as the
# game runs, then with its windowed flag [0x982BF0] set.  MW's menus take the mouse through the icon scroller every
# main-menu screen is built on (0x587D30, the MSG_MOUSE case at 0x587F7C; GAME.md 13.1 'Mouse'): the wheel over the
# icon strip (object 0xB39A7599, 340x70 units at (119,154) from the screen's centre) sends the scroller LEFT (wheel
# up) or RIGHT (wheel down), one item a notch (0x592F10), and a left click on the selection frame (0xB04669E3, 64x64
# at (136,157)) presses the highlighted item (BUTTON_PRESSED 0x0C407210, 0x587FBF) as Enter does.  No hover: the
# highlight moves only by the wheel.  The cursor is in front-end units, 640x480 over the whole window at any size
# (0x6C9B60: x * 640 / client width, y * 480 / client height, less 24 when the windowed flag is set), so the same
# window fractions pick the same item on any back buffer: run it with NFSRES=800x600, 1280x720 and 1920x1080 (the
# device's size, runtime/com.c res_pick; the 'com: device resolution' line).  'nsmouse scroll N' turns the wheel N
# notches up (DOM deltaY -N), so -1 is a notch down.  The windowed flag is only ever written by 0x6DE150, which no
# code calls (speed.exe v1.3), so it stays 0; it is set here by a poke to see the 24 units it takes off the cursor's y
# (the frame is 64 units tall, so a click at its centre still lands).  Every step waits for its screen or item
# (L-021); the cursor's place is checked where a click depends on it:
